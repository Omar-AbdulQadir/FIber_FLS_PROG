What's on the wire

Every multi-byte field is big-endian (MSB first). The first byte tells you the direction: A5 is a request, 5A is a response.

Erase the whole chip

PCA5 00 04 00 04 02 00 00 00 00 00
jig5A 00 04 00 00 00 00 00

Payload 02 000000 = scope chip, address ignored. Status 00 = OK, no data.

Stream 4 bytes, first chunk

PCA5 00 07 00 04 DE AD BE EF 00 00
jig5A 00 07 00 00 03 00 00 04 00 00

The reply's 3-byte data is bytes_done = 4. The client uses it to track progress.

How the jig assembles a request

TCP delivers a byte stream, not packets, so a frame can arrive split over several reads or merged with the next one. The protocol layer feeds every byte through this state machine and only acts when the last CRC byte lands.

A full programming session

The protocol is lock-step: the client sends one frame, then waits for its reply before sending the next. Here is the erase, program and verify sequence the PC tool will run.

Connection lifecycle

Transport_Poll() checks the W5500 socket state on every loop pass and moves it forward one step. The socket is non-blocking, so no call ever waits inside the WIZnet library.

Things to know before bring-up

  • CLIENTSet a long timeout on ERASE repliesA chip erase runs inside the handler, so the jig sends nothing until the flash clears BUSY. The W5500 keeps buffering incoming TCP meanwhile, and the 1 s stall timer is not armed because the frame already completed.
  • CLIENTCount bytes; don't ask for moreRead and write sessions close themselves when bytes_done reaches total. An extra READ_DATA or WRITE_STREAM_DATA after that returns ERR_SEQ.
  • FIRMWARECRC is a stub with partial coverageBesides always returning 0x0000, the request check in handle_complete_frame() only feeds CHIP, CMD and LEN-hi into the CRC. When the real CRC-16 lands, that buffer also needs LEN-lo and the payload.
  • FIRMWAREFailed sends are silentProtocol_SendResponse() ignores the result of Transport_Write(). If the socket dropped, the reply is lost and the PC simply times out.
  • FIRMWAREThe CHIP byte is echoed, not routedAny chip value is accepted and copied into the reply. Multi-chip selection is still deferred.
